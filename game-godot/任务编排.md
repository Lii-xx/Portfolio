## 三、T1：音效系统 - 代码框架（AI 独立完成）

### 目标
改造 `sound_manager.gd`，建立完整的音效播放框架，并在所有调用点接入信号。**此阶段不需要实际音频文件**，代码要能优雅处理"文件不存在"的情况。

### AI 负责的工作

1. **改造 `scripts/autoload/sound_manager.gd`**：
   - 替换 `AudioStreamGenerator` 为文件加载方式
   - 添加 `BGM_PATHS` / `SFX_PATHS` 路径字典（按大纲 2.2 节）
   - 添加 `_bgm_cache` / `_sfx_cache` 缓存
   - 实现 `play_bgm()` / `play_sfx()` / `set_bgm_volume()` / `set_sfx_volume()`
   - **关键**：`load()` 失败时静默跳过（用 `if stream == null: return`），不能报错

2. **创建目录**：
   - `assets/audio/bgm/`（空目录，加 `.gdignore` 或占位文件）
   - `assets/audio/sfx/`（同上）

3. **在调用点添加信号触发**（按大纲 2.3 节表格，共 16 处）：
   - `game_manager.gd`：play_card → `card_play`、monster_turn → `debuff`
   - `battle_screen.gd`：attack_hit / attack_heavy / block / heal / monster_die / player_hurt / battle BGM / boss BGM
   - `dice_effect.gd`：`dice_roll`
   - `poison_spread_effect.gd`：`poison`
   - 各效果脚本：`buff`
   - `campfire_screen.gd`：campfire BGM
   - `end_screen.gd`：victory BGM
   - 各 UI 按钮：`ui_click`（检查现有，补全缺失）

4. **验证**：
   - `run_project` 启动无报错
   - 控制台无 `load() returned null` 之外的错误
   - 触发各场景（出牌、受击等）不崩溃

### 用户需要补充
**无**。此阶段 AI 用空文件/不存在的路径也能跑（代码做了 null 检查）。

### 完成标志
- 游戏能正常启动运行
- 控制台无报错（允许有 "音频文件未找到" 的提示，但不能崩溃）
- 所有调用点已埋好信号

### 给 AI 的提示词
```

1. 改造 sound_manager.gd（参考大纲 2.2 节代码）
2. 创建 assets/audio/bgm/ 和 sfx/ 目录
3. 按大纲 2.3 节表格，在 16 个调用点添加 EventBus 信号触发
4. 关键：load() 失败要静默处理，不能报错崩溃
5. 完成后 run_project 验证无报错

注意：此阶段没有实际音频文件，代码要能优雅处理文件缺失。
```

## 十四、执行建议

### 给用户的建议

1. **先做 T0 素材准备**：并行下载音效和图片，不阻塞 AI 工作
2. **AI 任务可并行**：T1、T3、T5、T6、T8 互不依赖，可分别开新对话
3. **每个任务开新对话**：避免上下文过长导致 AI 出错
4. **每完成一个任务就 commit**：便于回滚

### 给 AI 的建议（每个任务开始时强调）

```
执行规则：
1. 严格按照任务描述执行，不要多做
2. 每改一个文件就测一次（run_project）
3. 遇到需要用户补充素材的地方，明确告知"需要 XX 素材"，不要跳过
4. 完成后列出：已改文件、已实现功能、待用户确认事项
5. 如果发现问题但不在本任务范围，记录但不修复
```

### 任务执行顺序推荐

**方案A：串行（稳妥）**
```
T0（用户准备素材）
→ T1（音效框架）
→ T3（核心动效）
→ T4（粒子）
→ T5（着色器）
→ T6（卡牌图代码）
→ T8（背景图代码）
→ T2（音效接入，需素材）
→ T7（卡牌图接入，需素材）
→ T9（背景图接入，需素材）
→ T10（氛围动效）
→ T11（整合测试）
```

**方案B：并行（高效）**
```
用户准备素材（T0）
同时开多个对话：
- 对话1：T1 → T2（音效线）
- 对话2：T3 → T4 → T10（动效线）
- 对话3：T5（着色器）
- 对话4：T6 → T7（卡牌图）
- 对话5：T8 → T9（背景图）
最后：T11（整合）
```

### 单次对话工作量参考

| 工作量 | 改动文件数 | 代码行数 | 适合任务 |
|--------|------------|----------|----------|
| 轻 | 1-3 个 | <50 行 | T2、T7、T9、T11 |
| 中 | 4-7 个 | 50-200 行 | T1、T3、T4、T5、T10 |
| 重 | 8+ 个 | >200 行 | 拆分，不要单次做 |

**红线**：单次对话改动超过 8 个文件或 200 行代码，AI 出错概率显著上升，应拆分。

## 十五、风险与应对

| 风险 | 表现 | 应对 |
|------|------|------|
| AI 改错现有代码 | 游戏功能异常 | 每个任务前 git commit，出错就回滚 |
| AI 上下文过长 | 后期遗忘前面的修改 | 每个任务开新对话，粘贴大纲 |
| 素材风格不统一 | 视觉割裂 | 用户准备素材时注意统一风格 |
| 着色器不兼容 | gl_compatibility 报错 | AI 抄简单示例，不用高级特性 |
| 粒子性能问题 | 帧率下降 | 控制数量，T11 整合时检查 |
| 动画冲突 | 卡牌闪烁/抖动 | T3 时注意与现有 hover/selected 协调 |
